# 설계 v2: 모든 앱을 읽고 쓰는 층

2026년 10월 15일 결정. 이전 설계는 `PRODUCT_SPEC.md` 에 남아 있고, 이 문서가 그보다 우선합니다.

## 만드는 대상

컴퓨터에서 벌어지는 일을 전부 읽고, 상황에 맞게 화면을 다시 짜고, 필요하면 대신 해 주는 층입니다.
운영체제 위에 올라가며 커널과 드라이버는 건드리지 않습니다.

대상 직군을 가리지 않습니다. 개발자만 쓰는 제품이 아닙니다.

## 이전 설계에서 바뀐 부분

이전 설계의 중심은 "형태만 보고 내용은 보지 않는다"였습니다. 센서가 호스트명, 상태 코드, 파일
경로만 보냈고, 동의 페이지도 그렇게 약속했습니다. 이 약속을 폐기합니다.

폐기하는 이유는 대상이 바뀌었기 때문입니다. 개발자 컴퓨터는 빌드 실패와 HTTP 500 같은 신호를
스스로 뱉습니다.

디자이너가 Figma에서 두 시간 작업하거나 사무직이 엑셀로 정산하는 동안에는 아무 신호도 나오지
않습니다. 직군을 가리지 않으려면 화면을 읽는 수밖에 없습니다.

## 센서 네 개

읽는 방법을 네 가지로 나눕니다. 같은 사실을 두 센서가 보내면 나중에 서로 어긋나므로 담당을 겹치지
않게 자릅니다.

### 1. 브라우저 확장 (기존)

브라우저 안을 맡습니다. 호스트명, 상태 코드, 지연시간, 탭 이동을 보냅니다. 페이지 안쪽이 필요하면
확장이 접근성 트리를 읽어서 보내고, 브라우저 창은 아래 UI Automation 센서에서 제외합니다.

### 2. UI Automation (신규)

브라우저 밖의 모든 앱을 맡습니다. 윈도우가 1990년대부터 제공해 온 접근성 창구를 씁니다. 앱이 자기
프로세스 안에서 직접 답하므로 남의 메모리를 읽지 않고, 권한 요청도 없습니다.

실측으로 확인한 범위는 이렇습니다. 한셀은 메뉴와 버튼이 이름 그대로 전부 나오고, 크롬은 창 제목이
나옵니다.

카카오톡은 이름 없는 상자 여섯 개만 나오고 대화 목록도 메시지도 나오지 않습니다. 앱이 답하는
함수를 구현해 두지 않았기 때문입니다.

실측으로 확인한 함정이 하나 있습니다. 창 제목이 애니메이션으로 계속 바뀝니다. 윈도우 터미널
제목이 0.5초마다 회전 표시 때문에 달라졌고, 제목 원문을 그대로 비교하면 신호가 끝없이 발생합니다.

### 3. 화면 캡처 (신규)

UI Automation으로 읽히지 않는 창을 맡습니다. 카카오톡이 그 예입니다. 화면을 그림으로 받아 로컬
모델로 읽습니다.

캡처 기반은 OBS를 씁니다. 라이선스 영향은 아래 항목에 적었습니다.

### 4. 데스크톱 에이전트 (기존)

파일 저장과 빌드, 테스트 출력 전환을 맡습니다. 지금 그대로 둡니다.

## 대신 해 주기

읽기만이 아니라 조작까지 합니다.

브라우저 안은 Chrome DevTools Protocol로 요소를 직접 집어서 누릅니다. 픽셀 좌표를 쓰지 않으므로
해상도가 바뀌어도 어긋나지 않습니다.

브라우저 밖은 두 갈래로 갈립니다. 접근성 창구가 답하는 앱은 요소의 사각형을 직접 물어볼 수
있습니다.

실측으로 확인했습니다. 크롬 창에 "최소화 버튼은 68x60 크기이고 가운데가 -171,30" 처럼 나옵니다.
창이 움직이거나 해상도가 바뀌어도 다시 물으면 되므로 어긋나지 않고, 이쪽은 화면을 찍을 필요가
없습니다.

답하지 않는 앱만 찍은 그림을 모델이 보고 좌표를 정합니다. 카카오톡이 그 경우이고, 느리고 틀릴 수
있습니다.

어느 쪽이든 마지막에 운영체제로 클릭을 보내는 방법은 같습니다. 윈도우는 SendInput을 씁니다.
좌표는 가상 화면 좌표계라 모니터가 여러 대면 음수가 나오고, 실측에서 -3840 까지 나왔습니다.

로그인은 공식 연동이 있는 서비스는 OAuth를 쓰고, 없는 서비스는 이미 로그인된 브라우저 세션을
그대로 씁니다. 아이디와 비밀번호를 저장해 두고 입력하는 방법은 2단계 인증에 막히고 약관이 금지하는
서비스가 많아서 쓰지 않습니다.

자격증명은 모델에 넣지 않습니다. 페이지에 직접 자동입력합니다.

## 그대로 쓰는 부분

이번 변경으로 버리는 코드는 없습니다. 다음은 신호가 어디서 오든 그대로 돕니다.

믿음 상태, 중요도 판단, 결정 엔진, 화면을 데이터로 그리는 구조, 되돌리기, 승인 엔진, 승인 카드,
감사 기록입니다. 센서를 두 개 더 붙이고 조작 쪽을 새로 만드는 작업입니다.

승인 엔진과 감사 기록은 대신 해 주기에 그대로 필요합니다. 위험한 작업 전에 사람에게 묻고 모든
실행을 기록에 남기는 구조가 이미 돌아가고 있습니다.

## 같이 결정해야 하는 항목 네 개

이 설계를 실행하면 다음 네 가지가 따라옵니다. 전부 결정이 필요하고, 아직 결정되지 않았습니다.

### 라이선스가 MIT에서 GPL로 바뀐다

OBS Studio는 GPL v2 이상입니다. 저장소에서 확인했습니다.

libobs를 링크해서 배포하면 이 저장소 전체도 GPL로 공개해야 합니다. 지금은 MIT입니다.

피하는 방법이 둘 있습니다. OBS를 묶지 않고 별도 프로그램으로 띄워 쓰는 방법과, 윈도우가 제공하는
Windows.Graphics.Capture API를 쓰는 방법입니다.

후자는 라이선스가 없고 프레임 한 장을 뜨는 데는 충분합니다. OBS가 더 나은 지점은 녹화, 인코딩,
송출, 씬 합성입니다.

### 동의 문구를 전부 다시 써야 한다

고칠 곳은 확장 옵션 페이지, 확장 manifest 설명, README 두 개, `PRODUCT_SPEC.md`, `BRANDING.md`,
`CLAUDE.md` 입니다. "형태만, 내용은 절대 수집하지 않습니다"는 더 이상 사실이 아닙니다.

동의 계층도 다시 짭니다. 지금 L0, L2, L3, L4로 나뉜 구조에 화면 캡처와 조작을 가장 넓은 옵트인
계층으로 붙입니다.

### 모델이 코드를 내놓지 않는다는 규칙과 충돌한다

`CLAUDE.md` 의 첫 번째 불변식은 모델이 실행 가능한 코드를 절대 내놓지 않는다는 규칙입니다. 모델은
데이터만 내놓고 Zod가 검증합니다.

같은 문제를 다루는 다른 도구는 반대로 갑니다. 도구를 REPL과 bash 두 개만 두고 모델이 Playwright
문법의 자바스크립트를 직접 씁니다. 모델이 가장 많이 학습한 데이터가 코드라는 이유입니다.

둘 중 하나를 골라야 합니다. 모델이 코드를 쓰게 하면 지금의 검증, 승인, 되돌리기가 전제부터 다시
짜입니다. 데이터만 내놓게 유지하면 조작 가능한 동작을 미리 정의해 둬야 합니다.

### 형태만 받는다는 전제 위의 테스트를 다시 봐야 한다

지금 있는 테스트 가운데 상당수가 센서가 형태만 보낸다는 전제로 상한과 정리 규칙을 검사합니다.
화면 캡처가 들어오면 그 전제가 바뀌는 부분이 생깁니다. 전부 버리는 작업은 아니고, 어느 테스트가
전제에 묶여 있는지 가려내는 작업입니다.

## 순서

1. UI Automation 센서. 화면 캡처 없이 창 제목과 앱 이름만 읽습니다. 개발자 신호 없이 화면이
   바뀌는지 여기서 판가름납니다.
2. Postgres를 컨테이너로 띄우고 `DATABASE_URL` 을 채웁니다. 코드 작업이 없습니다.
3. 화면 캡처. 캡처 기반을 정하고 라이선스 결정을 먼저 내립니다.
4. 동의 문구와 동의 계층 전면 개정.
5. 브라우저 조작. Chrome DevTools Protocol로 요소를 집어서 누릅니다.
6. 운영체제 조작과 로그인. 보안 설계가 통째로 필요합니다.

런타임과 바디와 Postgres는 컨테이너로 돕니다. 센서는 호스트에 설치됩니다. 컨테이너 안에는 읽을
창이 없기 때문입니다.
