# 동의 설계 v2: 내용을 보는 층을 따로 둔다

2026년 10월 16일. `DESIGN_V2.md` 가 정한 방향을 동의 쪽에서 구체화한 문서다.

## 왜 고치는가

지금 저장소는 서른 곳 가까이에서 "형태만 보고 내용은 절대 보지 않는다"고 약속한다. 확장 옵션
페이지, manifest 설명, README 둘, 제품 명세, 브랜딩 문서, 에이전트와 확장의 소스 주석까지다.

화면 캡처가 들어오면 그 약속이 거짓이 된다. 실측한 근거가 있다. 크롬 창 하나를 찍었더니 1936x1048
그림에 업무 화면이 통째로 들어왔다. 연동 소스별 행 수, 로트 번호, 불량률, 열린 플래그 건수가 전부
읽혔다. 카카오톡 창은 784x527로 찍혔고, 접근성으로는 이름 없는 상자 여섯 개만 나오던 창이다.

거짓인 채로 두면 안 된다. 문구를 고치는 작업과 캡처를 센서로 붙이는 작업은 같은 커밋에 들어가야
한다.

## 핵심 결정: 한 줄로 뭉뚱그리지 않는다

"이제 내용도 봅니다"로 바꾸는 방법이 가장 쉽고 가장 나쁘다. 지금 돌고 있는 센서 네 개는 여전히
형태만 보낸다. 파일 저장은 경로만 가고 내용은 안 간다. 통신은 호스트와 상태 코드만 간다. 창 감시는
앱 이름과 창 제목만 간다.

전부 내용을 본다고 적으면 사실이 아니고, 사람이 끌 수 있는 범위도 사라진다.

그래서 경계를 하나 긋는다. 지금까지의 계층은 형태만 보는 쪽에 남기고, 화면을 읽는 계층을 새로
만들어 그쪽만 내용을 본다고 적는다.

## 계층

지금 `SENSING_LAYERS` 에 열 개가 있다. `interactions`, `idle`, `visibility`, `dwell`, `tabs`,
`network`, `files`, `git`, `output`, `windows` 다. 전부 형태만 보낸다. 그대로 둔다.

여기에 `screen` 을 더한다. 성격이 다르므로 다음을 지킨다.

1. 기본값은 꺼짐이다. 다른 계층과 달리 켜는 행위가 한 번 더 필요하다.
2. 어느 앱의 창을 찍을지 사람이 목록으로 정한다. 전체 화면을 통째로 켜는 선택지를 두지 않는다.
   접근성으로 안 읽히는 창만 찍는 것이 이 계층이 존재하는 이유다.
3. 찍는 중이라는 사실이 화면에 보인다. 지금 "무엇을 감지 중" 표시가 계층 이름을 나열하는데,
   `screen` 은 어느 앱을 찍고 있는지까지 보인다.
4. 꺼도 이미 찍은 그림이 남아 있을 수 있으므로, 어디에 쌓이는지와 지우는 방법을 적는다.

## 문구를 어떻게 바꾸는가

바꿀 대상은 세 종류다.

**사실이 유지되는 문구는 건드리지 않는다.** 확장의 통신 형태 설명, 에이전트의 파일 저장 설명이
여기 해당한다. 이 센서들은 여전히 내용을 안 본다.

**전체를 대표하던 문구는 범위를 붙인다.** "형태만, 내용은 절대 수집하지 않습니다"는 제품 전체를
가리키던 문장이다. 어떤 계층이 형태만 보는지 적고, 화면 계층은 예외라고 적는다.

**새로 적어야 하는 문구를 만든다.** 화면 계층의 동의 문구다. 무엇을 찍는지, 어디에 저장되는지,
어디로 나가는지, 어떻게 끄는지다. 영어와 한국어 둘 다 같은 커밋에 넣는다.

## 어디까지가 이번 범위인가

문구와 계층과 표시까지다. 찍은 그림을 모델로 읽는 기능은 다음이다.

이번 작업이 끝나면 저장소가 말하는 것과 코드가 하는 것이 다시 일치한다. 캡처는 여전히 센서에
붙어 있지 않고 `DM_CAPTURE=1` 없이는 돌지 않는다. 붙이는 작업은 동의 문구가 먼저 참이 된 뒤에
한다.

## 바꿀 파일

`never content`, `shape only`, `형태만`, `내용은 절대` 로 찾으면 서른 개가 나온다. 전부 읽고
위 세 종류 중 어디인지 판단해야 한다. 기계적으로 바꾸면 사실인 문구까지 흐려진다.

주요 위치는 확장 옵션 페이지와 manifest, README 둘, `PRODUCT_SPEC.md`, `BRANDING.md`,
`CLAUDE.md`, `QUICKSTART.md`, 그리고 에이전트와 확장의 소스 주석이다.
