# Vision

Software today is a fixed set of applications that the human must learn, navigate, and
operate. Windows are arranged by hand; information is copied between tools; the human is
the integration layer.

Digital Matter inverts this. The software continuously reshapes itself around the user's
current context, intent, environment, and goals. The AI is not a feature inside an app —
the AI is the runtime, and the interface is its body.

## The organism metaphor

| Biological | Digital Matter |
|---|---|
| Senses | Events (`MatterEvent`) |
| Brain | Two-speed intelligence (reflex + deliberation) |
| Body | Structured, schema-driven UI |
| Abilities | Capabilities (native, MCP, HTTP, …) |
| Experience | Memory (working, episodic, preference, learned) |

## What we are proving in V1

> An AI runtime can observe meaningful events and autonomously reshape a structured
> interface around the current situation while remaining **stable, explainable,
> reversible, provider-independent, and permission-controlled.**

That single sentence is the entire V1 acceptance bar. Everything else (self-modifying
capabilities, multi-device swarm, spatial UI) is deferred research — see `ROADMAP.md`.

## Non-goals for V1

Full OS monitoring, arbitrary desktop control, autonomous payments/email, self-modifying
production code, fully autonomous Level 4 behavior, mobile apps, device swarms. We are
building a proof of the runtime, not an operating system.
